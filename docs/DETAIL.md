# 轮次删除

## 用途

在**同一个会话**里删掉一整轮对话，让它不再进入后续模型上下文。用于「本来在聊 A，手滑问了一件 B」这类污染上下文的误操作。

Session id、标题、工作区关联、之后的轮次、以及 append-only 的原始事件日志全部保留；被删的提问、回答与工具记录仍可在日志里审计与回放。

## 使用

每个已结束的顶层轮次，其助手回复的操作行里有一个垃圾桶图标。

1. 点垃圾桶：就地展开「删除 / 取消」，不起弹窗、不抢焦点。
2. 点「删除」：**当场生效**，这一轮立刻离开模型上下文，行被隐藏并标注已删除。
3. 刷新或重启后依然如此。

非 DeepSeek 适配器下退化为「下一次提问起生效」（界面会这么写），原因见下。

任务运行期间按钮置灰。重复删除幂等，不会写入第二条墓碑。

## 两种载体与两种时机

会话日志格式 v4 要求消息类事件匹配一个**开启**的 turn 和 step，因此「空 `system/message` 墓碑」只能落在下一轮。

但 v4 也允许 `user/message` 替换（内核 compaction 就是用 user 消息遮蔽被压缩区间），而空的 user 消息在 DeepSeek 序列化器里会被丢弃（`serialize.ts:123`），模型侧零残留。

- DeepSeek 适配器：`user/message` 空内容替换 → **当场删、零残留**。
- 其它适配器：把删除请求记成 `plugin:turn-delete/request`，在下一个开启的 step 内落 `system/message` 墓碑 → 零残留、慢一轮。

## 拒绝的情况

插件宁可拒绝，也不写一条会让会话变坏的记录：

| 情况 | 表现 |
|---|---|
| 这一轮还没结束 | 拒绝（`TURN_NOT_CLOSED`） |
| 这一轮已并入压缩摘要 | 拒绝并说明摘要无法单独摘除一轮（`TURN_COMPACTED`） |
| 这一轮携带**当前生效**的系统提示 | 拒绝，避免后续请求丢失系统提示（`TURN_PROTECTED`） |
| 任务正在运行 | 按钮置灰；接口返回 423（`AGENT_BUSY`） |

## 机制

内核的模型可见历史是事件日志经 `surfaceOp` 投影出来的「表面」。删除分两步：

1. 追加 `plugin:turn-delete/request`（`ignorable` 插件记录，不进表面）。
2. 下一个 step 开启时，追加一条**空内容的 `system/message`**：

```js
{ surfaceOp: { op: 'replace', startSeq, endSeq }, sourceEventSeqs: [...被遮蔽节点] }
```

空内容的 system 消息不投影任何 wire 消息，于是被替换的区间从派生历史里消失；日志本身一个字节都没改。随后追加 `plugin:turn-delete/result` 记录 applied / refused。

## 已验证

- 当前内核 `0.2.2-rc.3`：真实会话日志（1907 事件、19 轮）离线重放 + Host 全流程测试，包含关键回归——**删除落地后整条日志仍通过 v4 加载准入**。
- Host 路由在运行中的实例上实测：`200` / `202` / `404 TARGET_NOT_FOUND` / `415 INVALID_REQUEST` 均符合契约。
- 跨内核版本：`0.1.7-rc.2` / `0.2.0-rc.1` / `0.2.1-rc.5` / `0.2.2-rc.3` 对同一份日志产出**完全相同**的删除结果。

细节与复现命令见包内 `docs/TEST-REPORT.md`。若旧版本写坏了日志，用 `tools/repair-log.mjs` 修复（会自动备份）。

## 限制

- 仅顶层、已结束的轮次；subagent 会话不显示按钮。
- 「已删除」的视觉隐藏依赖 `data-turn-tail` / `data-chat-flow-kind` 两个 DOM 契约；内核没有公开的整轮可见性扩展点。这层呈现即使失效，模型上下文的删除仍然成立。
- 删除不会释放 token 计量记录，也不会改写历史统计。
